# Doru — план и архитектура

> Рабочий документ, актуализируется по ходу проектирования. Ведётся на русском.
> Статус: каркас v0 поднят; v0 закрыт (редактор, вкладки, i18n ×17, CI/CD, релизы).
> v1 закрыт: MCP-сервер наружу, чат с агентами (tool loop, разрешения), аудит AI-правок.

## 1. Идея и позиционирование

Тэглайн: **Doru — local-first генеалогия в эру ИИ** (англ. *Local-first genealogy
for the AI era*). Используется во всех описаниях продукта: README, сайт, релизы.

Название — от праиндоевропейского *\*dóru* («дерево»).

Десктопное приложение для работы с семейным древом с философией **local-first**:
данные принадлежат пользователю, живут в обычных папках на диске, работают офлайн.

Позиционирование — **«Obsidian от генеалогии»** (а не «VS Code от генеалогии» в полном
масштабе — полноценный extension-host в v1 строить не будем). Стилистика и подходы к
архитектуре — VS Code.

Ключевые свойства:

- **Local-first**: проект — обычная папка с текстовыми файлами и SQLite-базой дерева.
- **AI-native**: приложение одновременно MCP-хост и MCP-сервер; чат-панель с агентами,
  редактирование дерева и исследования через текстовый диалог; поддержка API-моделей
  (OpenAI/Anthropic/Gemini/Ollama) и ACP (позже).
- **Текстовые конфиги и темы**: настройки и стили — текстовые файлы, которые агент
  может переопределять по просьбе пользователя.
- **Прослеживаемость**: каждая правка агента проходит через журнал операций с
  указанием актора (пользователь / агент + модель + хеш промпта) — аудит AI-изменений
  является главным дифференциатором.

## 2. Конкурентный анализ (кратко)

- **Локальные десктопные**: Gramps (open-source, устаревший UI), Gramps Web
  (self-hosted + уже есть AI-фичи), MacFamilyTree (только Apple), RootsMagic /
  Family Tree Maker / Legacy (Windows-first, UI из 2000-х), GEDKeeper.
- **Облачные**: Ancestry, MyHeritage, FamilySearch, Geni, WikiTree — их moat —
  базы записей, а не редактор деревьев; напрямую не конкурируем.
- **Tree-Monk** (появился летом 2026): local-first генеалогия на Electron + React +
  SQLite + TS, офлайн, GEDCOM импорт/экспорт. Наиболее близкий по духу конкурент;
  наше отличие — MCP/агентный слой, текстовые конфиги, аудит AI-правок.
- **MCP + генеалогия**: ~15 мелких GEDCOM/FamilyTree MCP-серверов, все игрушечные
  (максимум ~16 звёзд). Ниша зрелого продукта пуста.
- **Obsidian**: экосистема плагинов для генеалогии растёт (obsidian-charted-roots) —
  и валидация, и паразитный конкурент.

## 3. Ключевые технологические решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Шелл | **Electron** | VS Code/Obsidian на нём; чистый TS; Monaco родной; зрелая кроссплатформенность. Tauri отброшен из-за Rust-якоря |
| Язык | **TypeScript**, strict, ESM | единый язык на всех слоях |
| UI | React + собственная workbench-оболочка | компоновка как у VS Code: activity bar, sidebar, editor area (monaco), panel, command palette, status bar |
| Репозиторий | npm workspaces, монорепо | слойность пакетов, как у VS Code |
| Хранилище дерева | **SQLite** в файле `tree.doru` | ACID, транзакции (атомарные пачки правок агентов), FTS5, JSON-колонки |
| Драйвер SQLite | **node:sqlite** (встроенный в Node ≥ 22.13; Electron 37+ подходит) | без нативных зависимостей и пересборок |
| Формат обмена | GEDCOM: импорт — готовой библиотекой, экспорт — своим писателем 7.0 | см. раздел 7 |
| MCP | официальный TS SDK `@modelcontextprotocol/sdk` | приложение = MCP-хост и MCP-сервер одновременно |
| Иконки | codicons (MIT, из VS Code) | визуальное родство с VS Code |
| Тесты | vitest (unit) + Playwright (e2e поверх Electron) | |
| Сборка/дистрибуция | electron-builder: dmg+zip / nsis / AppImage+deb+rpm; mac — notarization | |

## 4. Структура репозитория

```
doru/
├── apps/desktop/            # Electron: main, preload, window bootstrap
├── packages/
│   ├── platform/            # базовые сервисы (НЕ знают о генеалогии)
│   │   ├── di/              # DI-контейнер (tsyringe или свой минимум)
│   │   ├── lifecycle, events, commands, storage, logger
│   │   ├── configuration/   # settings.json (JSONC) + JSON Schema
│   │   ├── nls/             # локализация (раздел 9)
│   │   ├── theme/           # theme.json + theme.css, hot reload
│   │   └── keybindings/     # keybindings.json
│   ├── core/                # домен генеалогии (чистый TS, без UI)
│   │   ├── gedcom/          # импорт (read-gedcom) + собственный писатель 7.0
│   │   ├── model/           # Person, Family, Source, Place, Media
│   │   ├── ops/             # команды-операции + undo/redo
│   │   ├── index/           # поиск (FTS), индексы связей
│   │   └── validate/        # консистентность: циклы, даты, дубликаты
│   ├── workbench/           # UI-оболочка: layout, панели, командная палитра
│   ├── ai/                  # агентный слой: MCP client/server, connectors, аудит
│   └── features/            # доменный UI: tree, charts, sources, media, chat
├── themes/                  # встроенные темы: doru-light, doru-dark
└── docs/
```

Граница: `core` не импортирует `platform` и ничего про UI; UI и агенты обращаются к
одной модели через сервисы.

## 5. Процессная модель

```
┌─────────────────────────────────────────────────────────────┐
│ Main Process (Node)                    ┌──────────────────┐ │
│  файлы, watcher (chokidar), меню,      │ Extension Host   │ │
│  протокол doru://, safeStorage,        │ (Node, отдельный)│ │
│  lifecycle MCP-серверов, обновления    │ плагины, MCP-    │ │
└────────────────┬─────────────────────── │ серверы наружу  │ │
                 │ IPC                    └──────────────────┘ │
┌────────────────▼────────────────────────────────────────────┐
│ Renderer (Chromium): Workbench UI (React)                   │
└─────────────────────────────────────────────────────────────┘
        └── Utility Process: парсинг больших GEDCOM, миниатюры
```

- **Main** — только оркестрация и доступ к ОС, бизнес-логики нет. SQLite трогает
  только main; UI и агенты ходят через инструменты/IPC.
- **Extension Host** — изолирует плагины и внешние MCP-серверы (дочерние процессы).

### Вкладки (tabs) и мультипроектность

- В editor area одновременно открыто **несколько проектов — каждый во вкладке**,
  как в VS Code: переключение, закрытие, drag для перестановки. Активный таб
  определяет контекст команд и агент-сессии. **Реализовано.**
- Внутри проекта: редактор персоны (полные даты с точностью), **семейные связи
  (родители/партнёры/дети с пикером персон)**, **источники с цитатами**,
  заметки, raw-вид GEDCOM (read-only). **Всё реализовано.**
- Main держит `Map<путь, ITreeStore>`; renderer хранит список открытых
  проектов; повторное открытие переключается на существующий таб.
- Недавние проекты + **восстановление прошлой сессии** (`session.json` в
  userData) — реализовано.

## 6. Формат проекта и самовосстановление

Проект — **обычная честная папка** (без пакетов/UTI на macOS), имя любое.
Внутри — шаблон:

```
«Семья Ивановых»/
├── tree.doru              # SQLite: дерево (application_id, user_version)
├── settings.json          # текст, JSONC
├── theme.css              # текст
├── history.jsonl          # аудит операций, текст (git-friendly)
├── media/
└── export/
```

- Идентификация проекта — по наличию `*.doru` (v1: ровно один `tree.doru`;
  структура допускает несколько деревьев в одной папке в будущем).
- Файловая ассоциация `.doru` → приложение: двойной клик открывает дерево,
  корень проекта = родительская папка. Альтернатива — «Open Project…» по папке.
- **Открытие идемпотентно**: если чего-то нет — молча создаём недостающее
  (mkdir, пустой sqlite со свежим user_version, дефолтные settings/theme),
  затем миграции схемы по `user_version`, затем открытие. Никаких ошибок и
  модалок пользователю; всё фиксируется в лог приложения.
- Битый `tree.sqlite` (corrupted, не missing) — единственное исключение:
  восстановление из журнала/бэкапа + честная запись в лог, без паники в UI.
- SQLite: `journal_mode=DELETE` (не WAL — чтобы рядом не было `-wal`/`-shm`
  файлов в документной папке), магический `application_id` брендирует файл,
  `user_version` — миграции схемы.

## 7. GEDCOM

- **Импорт**: `read-gedcom` (arbre-app) — MIT, ноль зависимостей, толерантный
  парсинг, определение кодировок (ASCII/CP1252/UTF-8/UTF-16/CP850...), покрытие
  5.5/5.5.1, progress-callback. Альтернативы: `topola` (парсинг + визуализация,
  Apache-2.0, активный), `tmcw/gedcom` (простой → JSON, ISC).
- За интерфейсом `GedcomImporter` — своя прослойка санитайзинга (ANSEL, BOM,
  кривые файлы от коммерческих программ).
- **Экспорт**: собственный писатель каноничного GEDCOM 7.0 (готовых TS-писателей
  нет; писать существенно проще, чем парсить).
- Топола (`topola`) — кандидат на диаграммы (pedigree, fan chart, kinship).

## 8. AI/агентный слой (`packages/ai`)

```
AgentConnector (интерфейс)
 ├── MCPConnector          # приложение как HOST: FamilySearch, Gramps Web,
 │                         #  Ollama, web-search, filesystem
 ├── APIConnector          # прямые: OpenAI, Anthropic, Gemini
 ├── ACPConnector          # позже, когда протокол созреет
 └── LocalConnector        # Ollama/lmstudio через API
```

- Приложение одновременно **MCP-хост и MCP-сервер**. Наружу (`doru` server):
  `tree.query`, `tree.get`, `tree.stats`, `tree.edit`, `sources.add`,
  `notes.write`, `charts.render` — любой Claude Desktop/Cursor может вести
  дерево. **Реализовано**: запуск `doru --mcp-server <папка проекта>`
  (stdio, MCP SDK); в Claude Desktop: `{"command": "doru", "args": ["--mcp-server", "/path/to/project"]}`.
- **MCP-хост реализован**: секция `"mcp": { "servers": [...] }` в `doru.json`
  (stdio-серверы, env); инструменты внешних серверов попадают в tool loop
  агента с префиксом `<имя сервера>:<инструмент>` и тем же пермишн-гейтом.
- **ACP реализован**: `"ai": { "provider": "acp", "command": "...", "args": [] }` —
  приложение выступает ACP-клиентом (SDK `@agentclientprotocol/sdk`),
  передаёт агенту наш doru MCP-сервер (субпроцесс `doru --mcp-server`,
  актор `agent:acp:<command>` через env) + внешние MCP-серверы из конфига;
  `session/request_permission` агента маршрутизируется в UI-карточку Allow/Deny.
- **Система разрешений** (паттерн tool confidence из VS Code): первый вызов
  инструмента — запрос пользователю, политика в `settings.json`; агент может
  переопределить её по просьбе пользователя. **Реализовано** для чата:
  `tree.query`/`charts.render` — allow по умолчанию, мутирующие инструменты —
  ask с карточкой Allow/Deny в панели.
- **Chat-панель** в workbench: диалог с рендером tool calls, дифы предлагаемых
  правок с кнопкой Apply. **Реализовано**: агентный цикл (до 8 итераций),
  коннектор OpenAI-совместимых API (OpenAI/Ollama/OpenRouter), конфиг
  `userData/doru.json` (JSONC), события разрешений через IPC.
- Каждая мутация агента идёт через `ops` → попадает в `history.jsonl`
  (актор: user | `agent:{host}/{model}#{promptHash}` | `agent:mcp`).
  **Реализовано**.

## 9. Локализация (закладывается сразу)

Модель VS Code: ключ строки = английский исходный текст, переводы — в
JSON-бандлах по локалям, отсутствующий перевод молча откатывается к ключу
(английскому).

- Бандлы: `locales/<lang>.json` с именами ключей в стиле
  `workbench.commandPalette.open`; базовый бандл `en` генерирует типы —
  обращения к ключам проверяются компилятором; отсутствующий в переводе ключ
  молча откатывается к английскому.
- **Набор локалей повторяет языки VS Code** (17): `en`, `ru`, `fr`, `de`, `it`,
  `es`, `pt-br`, `cs`, `pl`, `hu`, `bg`, `el`, `tr`, `ja`, `ko`, `zh-cn`, `zh-tw`.
  Резолвинг локали (`resolveLocale`): точное совпадение → `zh-hans`/`zh-hant`
  → маппинг по базе языка (`pt` → `pt-br`, `zh` → `zh-cn`) → `en`.
- Локаль: **всегда системная** (`navigator.language`, решение принято — без
  ручного переключения); `settings.json` проекта пока не имеет потребителя
  (создаётся в шаблоне, схема готова).
- Правило для кода: **никаких захардкоженных строк в UI** — всё через nls-ключи.
- Идентификаторы MCP-инструментов остаются стабильными английскими (агентам
  нужна стабильность), локализуются только описания.
- Языковая политика репозитория — в `AGENTS.md` (английский для кода и постоянных
  документов; русский допустим в промежуточных рабочих документах).

## 10. Кроссплатформенные пункты

- Пути/файлы — только через абстракции; watcher — chokidar.
- Нативные меню: отдельные шаблоны под mac (app menu) и win/linux.
- Файловая ассоциация `.doru` + протокол `doru://open?path=...` (реализовано).
- **Иконка**: векторный `apps/desktop/resources/icon.svg` — источник истины;
  `npm run icon -w @doru/desktop` рендерит `icon.png` (1024×1024, sharp);
  icns/ico electron-builder производит сам из PNG при сборке.
- Секреты (API-ключи моделей) — Electron `safeStorage` (Keychain/DPAPI/libsecret):
  ключ из `doru.json` мигрирует в зашифрованное поле при первом чтении;
  переопределение через env `DORU_AI_API_KEY`/`DORU_AI_MODEL` (реализовано).
- **Темы из проекта**: `theme.css` загружается при открытии проекта, live-reload
  через fs.watch (реализовано). **Встроенные темы**: `doru-dark`/`doru-light`
  поставляются в resources (`themes/`), выбор отдельно для тёмной и светлой в
  `doru.json` (`theme.dark`/`theme.light`), какая применяется — решает ОС
  (nativeTheme), hot-reload конфига; приоритет: базовая палитра < встроенная
  тема < theme.css проекта (реализовано).
- **Подпись/нотаризация**: релизный workflow подписывает mac/win и нотаризует
  mac при наличии секретов репозитория (см. CONTRIBUTING.md), без них — unsigned.
- e2e прогоняется на всех трёх платформах.
- **CI/CD (GitHub Actions)**: CI на push/PR (matrix: тесты, typecheck, сборка,
  e2e на Linux); release по тегу `v*` — matrix mac/win/linux собирает
  установщики (dmg/zip, nsis, AppImage/deb) и публикует их в GitHub Release.
  Подпись/нотаризация — при наличии секретов репозитория (см. раздел 10).

## 11. Фазирование

1. **v0** — скелет: platform + workbench-оболочка + core (импорт/экспорт GEDCOM,
   ops/undo, tree-вью, SQLite-проект с самовосстановлением), несколько проектов
   во вкладках, recent projects. Уже полезно как простой редактор.
2. **v1** — MCP-сервер наружу + chat-панель с одним connector + аудит правок.
   Момент «вау» и уникальность. **Готово** (см. раздел 8).
3. **v2** — MCP-хост (внешние серверы), ACP. **Готово** (см. раздел 8).
   Plugin API / extension host — **выкинут из плана** (возможно в будущем).

## 12. Открытые вопросы

- Синхронизация между машинами / CRDT — не блокирует v0-v2; журнал операций
  оставлен как потенциальная база.
- Несколько деревьев в одной папке проекта — **решено: не делаем.**
- Мобильная версия (Capacitor, как у Obsidian) — **решено: пока не делаем,**
  но архитектура не должна ставить блокеров (чистые абстракции над системным
  API, никаких Electron-импортов в core/platform).
- Монетизация — **решено: не делаем.**
- **ACP — сделано** (см. раздел 8); MCP-хост — сделано.
- Диаграммы (Topola) и автообновление — **вынесены за рамки этого плана**,
  вернёмся в следующем цикле планирования.
- Plugin API / extension host — **не в этом плане**; архитектура (чистые слои,
  сервисы) оставляет возможность вернуться.
